Public API ​

HaloGrids Module

Module HaloGrids

A ground-up redesign of ImplicitGlobalGrid.jl's halo-exchange core: explicit Grid objects instead of module-global mutable state, per-grid-owned communication caches instead of module-let singletons, a single per-field halo-width concept instead of overlaps/halowidths, and an explicit two-phase halo_exchange_start!/halo_exchange_finish! API for communication/compute overlap.

See REDESIGN_PLAN.md (in the ImplicitGlobalGrid.jl / HaloGrids.jl repo root) for the full design rationale and phased build plan this package follows.

Core types

  • Topology: explicit Cartesian MPI process topology.

  • Grid: sizing + owned ExchangeCache layered onto a Topology.

  • Field: a local array paired with its own per-dimension halo width.

Functions

  • topology, grid, field

  • halo_exchange_start!, halo_exchange_finish!, update_halo!

  • gather!

  • global_sum/global_max/global_min/global_norm, global_reduce/global_allreduce

  • Coordinate helpers, per field: nglobal/nx_g/ny_g/nz_g, iglobal/ix_g/iy_g/iz_g, coord_g/x_g/y_g/z_g

  • save_hdf5/load_hdf5! (optional, requires using HDF5)

  • save_pvtk (optional, requires using WriteVTK)

Topology ​

HaloGrids.Topology Type
julia
Topology{N}

An explicit, independently-constructed Cartesian MPI process topology. No global mutable state: every Topology (and every Grid built on top of it) is a plain value threaded explicitly through calls, which is what makes multiple concurrent grids of different sizes work by construction rather than by careful discipline.

Fields:

  • comm::MPI.Comm: the Cartesian communicator (a fresh communicator derived from the input comm, never shared with another Topology, even one built from the same parent communicator).

  • dims::NTuple{N,Int}: number of ranks along each dimension.

  • periods::NTuple{N,Bool}: periodicity of each dimension.

  • rank::Int: this process's rank within comm.

  • coords::NTuple{N,Int}: this process's 0-based Cartesian coordinates.

  • neighbors::NTuple{N,NTuple{2,Int}}: neighbors[d] = (lo, hi), the ranks of the lower- and upper-side neighbor in dimension d, or MPI.PROC_NULL if there is none (non-periodic domain boundary).

source
HaloGrids.topology Function
julia
topology(dims::NTuple{N,Integer}; comm=MPI.COMM_WORLD, periods=ntuple(_->false,N),
         disp=1, reorder=true) :: Topology{N}

Build a Cartesian MPI process Topology. dims gives the desired number of processes along each dimension; an entry of 0 lets MPI choose (via MPI.Dims_create) a balanced size for that dimension. Only 2D and 3D topologies are supported.

Each call creates its own new communicator (via MPI.Cart_create), even when given the same parent comm as another call — this is the actual mechanism that lets multiple Topology/Grid instances coexist without cross-talk.

Grid ​

HaloGrids.Grid Type
julia
Grid{N}

Sizing information layered onto a Topology, plus the per-grid ExchangeCache it owns. No halo-width or field information lives here — that is the responsibility of Field — which is what fixes the old package's overlaps confusion (one halo-width concept, declared per field, instead of two conflated grid-wide/per-field ones).

There is no module-global "current grid": every Grid is an explicit value returned by grid and passed explicitly to every function that needs it (update_halo!, gather!, ...). This is what makes multiple, independently sized, concurrently live grids work by construction.

Fields:

  • topology::Topology{N}

  • nlocal::NTuple{N,Int}: the local array size every Field exchanged on this grid must have, in every dimension (uniform per rank).

  • origin::NTuple{N,Float64}, origin_on_vertex::Bool, centered::NTuple{N,Bool}: physical-coordinate metadata, kept for migration ease from the old package.

  • excache::ExchangeCache: this grid's own communication scratch state.

source
HaloGrids.grid Function
julia
grid(topology::Topology{N}, gridsize::NTuple{N,Integer};
     origin=ntuple(_->0.0,N), origin_on_vertex=false,
     centered=ntuple(_->false,N), threaded_pack=false,
     global_size=false, halowidths=ntuple(_->1,N)) :: Grid{N}

Construct a Grid from an explicit Topology and, by default, the local array size every field on this grid will share — gridsize means nlocal, exactly as before, when global_size=false (the default). centered[d]=true requires nlocal[d] to be even when origin_on_vertex=true, or odd when origin_on_vertex=false — the same coherence rule the old package enforced at grid-creation time, since it determines whether the origin can fall exactly on a vertex/cell-center.

Pass global_size=true to give gridsize as the global domain size instead: nlocal is then derived per dimension via nlocal_from_global, inverting nglobal's own formula, using halowidths (default 1 in every dimension, matching field's own default) — errors clearly, naming the dimension, if gridsize[d] does not divide evenly across topology.dims[d] once halowidths[d] is accounted for. halowidths here is used only for this computation, exactly like the manual nl = core ÷ dims[d] + 2*hw[d] arithmetic the Restart with a different number of ranks guide section and test_hdf5_io.jl's restart test already do by hand — Grid still stores no halo-width information of its own (that remains Field's responsibility). Consequently, only a Field built with the same halowidths used here will actually see gridsize as its nglobal; a field with different halowidths on this same Grid sees a different (still well-defined, just different) global size, exactly as nglobal's own docstring already describes for manually-built grids.

threaded_pack=true opts this grid's exchanges into splitting large pack/unpack copies across Threads.@spawn tasks (only when Threads.nthreads() > 1 and a given field's halo slab is large enough to be worth it — see THREADED_PACK_MIN_LEN in halo_exchange.jl). Off by default: it trades a real, unavoidable per-call allocation (each spawned task allocates, regardless of how large the copy is) for wall-clock speed on large transfers, which is the right trade only when you've asked for it — see "Performance, memory footprint, and GC-pressure goals" in REDESIGN_PLAN.md for the measurements behind this default.

HaloGrids.nlocal_from_global Function
julia
nlocal_from_global(topology::Topology{N}, nglobal::NTuple{N,Integer},
                    halowidths::NTuple{N,Integer}) :: NTuple{N,Int}

Invert nglobal's formula (nglobal[d] = dims[d]*(nlocal[d]-2*hw[d]) + 2*hw[d]*!periods[d]) to find the local array size (halo included) every rank in topology must use so that a Field built with halowidths sees exactly nglobal as its global domain size, in every dimension. Field ​

HaloGrids.Field Type
julia
Field{T,N,A}

A local array paired with its own per-dimension halo width. Not tied to any Grid at construction time — the Grid is supplied later, at the exchange call site — so a Field never needs to know about multi-grid concerns, and the same field could (in principle) be exchanged against different grids in different calls.

halowidths[d] is the number of boundary cells, in dimension d, that are exchanged with neighbors: the outer halowidths[d] cells on each side of the local array are treated as halo (overwritten on receive), and the adjacent interior cells of the same width are what gets sent to the neighbor. This replaces the old package's separate overlaps/halowidths pair with a single concept: there is no grid-wide default and no notion of a halo wider than what each field itself declares.

overlaps[d] is the number of array lines, including the halo, that neighboring ranks share in dimension d. It defaults to 2*halowidths[d] (the sent strip is directly adjacent to the halo); larger values move the sent strip further inward, as ImplicitGlobalGrid does for staggered or padded arrays. See overlaps.

source
HaloGrids.field Function
julia
field(A::AbstractArray; halowidths::NTuple{N,Integer} = ntuple(_->1,N),
      overlaps::NTuple{N,Integer} = 2 .* halowidths) :: Field

Wrap array A as a Field with the given per-dimension halowidths, defaulting to a width of 1 in every dimension (the common case for a single-cell-wide stencil). Requires, for every dimension d: halowidths[d] >= 1 and 2*halowidths[d] <= size(A,d) (the local array must be at least wide enough to hold two non-overlapping halo copies — one sent, one received — in every dimension) and 2*halowidths[d] <= overlaps[d] <= size(A,d). eltype(A) must be a bits type.

This default lives here, on the constructor, and nowhere else — there is still no grid-wide or package-wide halowidths default stored anywhere, so different Fields (even wrapping the same array in different calls) remain free to use different widths. This is what lets update_halo!'s bare-AbstractArray convenience methods mix a default-width array and an explicitly-field-wrapped, custom-width array in the very same call.

Halo exchange ​

HaloGrids.update_halo! Function
julia
update_halo!(grid::Grid, fields::Field...; dims::Tuple=ntuple(identity, ndims(grid)), region::Symbol=:full) :: Nothing

Update the halo of fields on grid: halo_exchange_start! immediately followed by halo_exchange_finish!. Prefer this unless you specifically want to overlap communication with other work. region=:full propagates edges and corners sequentially; region=:faces fills only faces and permits all requested dimensions to remain pending in the split API. See halo_exchange_start!.

source
HaloGrids.halo_exchange_start! Function
julia
halo_exchange_start!(grid::Grid, fields::Field...; dims::Tuple=ntuple(identity, ndims(grid)), region::Symbol=:full) :: ExchangeHandle

Start a halo exchange for fields on grid, over dimensions dims (an NTuple of Ints, processed in the given order). Every dimension except the last is completed fully synchronously before returning (sequential-dimension correctness, for correct corners); the last dimension's receive (and, for a single-rank-periodic dimension, unpack) is left outstanding. Only one exchange may be in flight per Grid at a time — starting a second before finishing the first raises an error; multiple different grids remain fully concurrent.

With region=:faces, exchange only face halos, excluding transverse halo cells in other grid dimensions. Every requested dimension remains pending until finish; edges and corners stay unchanged. Use this for axial stencils that do not read diagonal halos. Extra trailing field dimensions (such as batched components) retain their full extent. Repeated dimensions are rejected in face mode. Peers must use the same region, dimensions, and field order. Keep input fields unchanged while computing into separate output storage.

In both modes, every requested dimension d of every field must satisfy overlaps[d] + halowidths[d] <= size(data,d), so the sent strip holds only owned cells (3*halowidths[d] with default overlaps). Dimensions with a single rank and no periodicity are exempt, since nothing is sent there.

Call halo_exchange_finish! exactly once on the returned handle to complete it; finishing a handle twice, or a stale handle after a newer start, raises an error. update_halo! is a convenience wrapper that does both.

source
julia
halo_exchange_start!(grid::Grid, args::Union{Field,AbstractArray}...; dims=..., region=:full) :: ExchangeHandle
update_halo!(grid::Grid, args::Union{Field,AbstractArray}...; dims=..., region=:full) :: Nothing

Convenience forms of halo_exchange_start!/update_halo! that accept bare arrays as well as Fields, in any mix, in the same call: a bare AbstractArray is wrapped with field's default halowidths (currently 1 in every dimension), while a Field keeps whatever explicit halowidths it was built with — so a single call can give different arrays different widths without every array needing to be pre-wrapped:

julia

source
HaloGrids.ExchangeHandle Type
julia
ExchangeHandle

Returned by halo_exchange_start!; pass it to halo_exchange_finish! to complete the exchange. Opaque — its fields are internal.

With the default region=:full, halo exchange is sequential across Cartesian dimensions (dimension 2's packing must read what dimension 1's unpacking wrote, to get corners right), halo_exchange_start! performs every dimension but the last fully synchronously, and only the last dimension is actually left outstanding in the handle — this is the honestly-documented scope limit of the communication/compute overlap for full exchange. region=:faces excludes transverse halo cells and leaves every requested dimension outstanding.

HaloGrids.@hide_halo_communication Macro
julia
@hide_halo_communication grid fields... [boundary_width=widths] begin
    @parallel ranges kernel!(...)
    boundary_updates...
end

ParallelStencil integration for overlapping a ranged computation with halo exchange. ParallelStencil must be loaded so that the optional extension is active.

The first nonempty statement must be exactly one explicitly ranged @parallel call. The macro partitions ranges into disjoint outer slabs and an inner box, launches the kernel over every outer slab, executes the remaining statements as boundary updates, synchronizes ParallelStencil, starts halo exchange for fields, launches the same kernel over the inner box, and finally finishes the exchange. halo_exchange_finish! runs from a finally clause if the inner launch throws.

By default the partition width is the componentwise maximum of the exchanged fields' overlaps - halowidths (their halo widths, for default overlaps): the depth of the strip that is sent. Override it with boundary_width=(bx, by) or boundary_width=(bx, by, bz). A width at least that default moves more work before the exchange and leaves less work available for overlap without changing the result; a smaller width sends cells before the kernel has updated them. Every width must be positive and match the dimensionality of ranges. If any range length is at most twice its width, the macro instead launches the full kernel, executes the boundary updates, synchronizes, and performs a blocking update_halo!. ParallelStencil's automatic partitioner also requires every range to start at 1.

The boundary statements must update only data outside the inner box and must not depend on unfinished inner values. They run before packing and are useful for physical boundary conditions. Halo exchange then overwrites provisional boundary values on internal process interfaces. As with halo_exchange_start!, only the final Cartesian dimension remains pending and can overlap the inner launch; earlier dimensions finish synchronously.

source

See halo exchange for ordering and overlap constraints, and hiding communication and boundary widths for the ParallelStencil schedule, sizing examples, sketches, and safety rules.

Communication buffers ​

HaloGrids.ExchangeCache Type
julia
ExchangeCache

Per-Grid-owned scratch state for halo exchange: raw send/recv byte buffers and the MPI request array. Full exchange reuses one slot per field position; face exchange reserves separate slots per dimension and field position so all requested dimensions can remain pending together. This is a mutable struct whose fields are reassigned as buffers grow — never a module-level let-captured variable — precisely so that two live Grids never share or clobber each other's buffers/requests, and so that growing a buffer is a plain struct-field store rather than the reassignment of a closure-captured local (which Julia would box, and which we measured as slower than the allocation it would avoid).

pending guards the "one in-flight exchange per Grid" v1 restriction: it is set by halo_exchange_start! and cleared by halo_exchange_finish!, so a second start! before a matching finish! errors instead of corrupting buffers shared between the two overlapping exchanges. epoch counts started exchanges; each handle records the epoch it was started in, so finishing a handle twice, or finishing a stale handle while a newer exchange is pending, errors instead of unpacking the newer exchange's buffers into the old fields.

reqs holds one distinct MPI.Request per slot, reused in place by every Isend/Irecv! so a steady-state exchange allocates no request objects.

threaded_pack is the opt-in flag (set at grid construction, see grid) for splitting large pack/unpack copies across Threads.@spawn tasks. It defaults to false: real OS-thread parallelism here has a real, unavoidable allocation cost (each spawned task allocates, measured ~500-670B regardless of chunk size — see "Performance, memory footprint, and GC-pressure goals" in REDESIGN_PLAN.md), so it must never turn on under a caller who hasn't asked for it and expects the package's zero-allocation default to hold.

gpu_cache is an untyped (Ref{Any}) slot, nothing until a GPU extension (CUDA/AMDGPU) lazily constructs its own device-buffer cache struct into it on this grid's first GPU-array exchange — see src/backend.jl. The core package never inspects its contents; keeping it Any-typed here means the core doesn't need to know the GPU cache's concrete type, and a CPU-only grid that never touches a GPU array never allocates one.

Gathering arrays ​

HaloGrids.gather! Function
julia
gather!(A, A_global, topology_or_grid; root=0)

Gather local array A from each member of the Cartesian process topology into one large array A_global on the root process (A_global may be nothing on every other process). size(A_global) must equal size(A) .* dims, where dims are the process-topology dimensions. Every rank must pass an A of the same size. ndims(A) <= ndims(A_global) <= ndims(topology); topology dimensions beyond ndims(A_global) must be 1. Invalid arguments on any rank raise an error on every rank.

Uses the exact zero-copy technique from the old package (a derived MPI.Types.create_subarray + create_resized + a single Gatherv!/VBuffer call — no manual pack loop); the only change is that dims/comm are read directly off the explicit Topology/Grid argument instead of an implicit current-grid lookup.

MPI/HDF5 file I/O ​

HaloGrids.save_hdf5 Function
julia
save_hdf5(grid::Grid, field::Field, path; name="field", group="/", mode="w")
save_hdf5(grid::Grid, fields::NTuple{M,Field}, path; names, group="/", mode="w")

Write one or more Fields' rank-local interior data (halo cells that duplicate a neighbor's data are never stored) to an HDF5 file, using the Grid's Cartesian topology to place each rank's block at its correct offset in a single shared, per-field global dataset. See load_hdf5! for reading it back.

This is a stub method: calling it without HDF5 loaded raises this error rather than a bare MethodError. Loading HDF5 (using HDF5) resolves the call to HaloGridsHDF5Ext's implementation via ordinary multiple dispatch — the same "declare a stub in core, add methods from the extension" pattern as pack_target in backend.jl — so no Base.get_extension lookup is needed at the call site.

See the "MPI/HDF5 file I/O" guide for the on-disk layout, the interior/halo storage convention, and why every rank must call this together (there is no parallel-HDF5 build to make a true collective write meaningful here, so ranks instead take turns under an internal MPI.Barrier-synchronized schedule).

With mode="w" (the default) the file is written as path * ".tmp" and renamed to path only after every rank has written, so an interrupted save leaves any previous file at path intact. Other modes write in place.

HaloGrids.load_hdf5! Function
julia
load_hdf5!(grid::Grid, field::Field, path; name="field", group="/", repartition=false)
load_hdf5!(grid::Grid, fields::NTuple{M,Field}, path; names, group="/", repartition=false)

Read a file written by save_hdf5 back into the given Field(s), mutating their arrays in place. Halo cells that have a real neighbor are not restored (they were never saved) — call update_halo! afterward to repopulate them.

Set repartition=true to restart with a different Cartesian process shape, rank count, or local array size. Construct the destination grid and fields first: each field must retain its saved global shape, halo widths, element type, and periodicity. Only uniform per-rank decompositions are supported. Each rank reads its owned hyperslab directly from the global dataset; neighbor halos remain untouched until update_halo!. The default retains strict checks of the saved topology dimensions and local size.

This is a stub method, resolved the same way as save_hdf5 once using HDF5 loads HaloGridsHDF5Ext; see its docstring and the "MPI/HDF5 file I/O" guide for the full rationale.

Parallel ParaView (pvtk) I/O ​

HaloGrids.save_pvtk Function
julia
save_pvtk(grid::Grid, field::Field, path; name="field", dx=ntuple(_->1.0,N))
save_pvtk(grid::Grid, fields::NTuple{M,Field}, path; names, dx=ntuple(_->1.0,N))

Write one or more Fields to ParaView's parallel VTK XML image-data format (.pvti header + one .vti piece per rank), using WriteVTK.jl's MPI-aware pvtk_grid. This is a write-only extension: ParaView (or ReadVTK.jl, used only in this repository's own tests) is the reader, so there is no load_pvtk! counterpart to save_hdf5/load_hdf5!.

Unlike save_hdf5, which trims halo cells that duplicate a neighbor's data, save_pvtk writes each rank's entire local array, halo included — parallel VTK requires neighboring pieces to overlap at shared boundaries so ParaView can stitch them into one seamless volume. Since Grid stores no physical spacing, dx must be supplied explicitly (same convention as coord_g/x_g/y_g/z_g), defaulting to unit spacing in every dimension.

path is a base name with no extension, not a literal file path: a call with path="fields" produces fields.pvti plus a fields/ subdirectory holding one fields_<rank+1>.vti file per rank — this is WriteVTK's own pvtk_grid convention, not save_hdf5's (whose path is the literal file to write).

Every field passed to one save_pvtk call must share the same halowidths: mixed halo widths would imply a different global domain size per field (see nglobal/iglobal), which cannot be represented by the single shared coordinate grid one pvtk_grid file set uses — save fields with different halowidths in separate calls instead.

Periodic topologies are not supported. Parallel VTK extents are a flat, non-wrapping index space, so a periodic dimension's wrap-around halo cannot be written as a contiguous extension of the same coordinate axis without producing spatially folded (incorrect) geometry; save_pvtk raises a clear error naming the offending dimension(s) rather than silently writing wrong data.

This is a stub method: calling it without WriteVTK loaded raises this error rather than a bare MethodError. Loading WriteVTK (using WriteVTK) resolves the call to HaloGridsWriteVTKExt's implementation via ordinary multiple dispatch — the same "declare a stub in core, add methods from the extension" pattern as save_hdf5 and pack_target in backend.jl — so no Base.get_extension lookup is needed at the call site.

See the "Parallel ParaView (pvtk) I/O" guide for the on-disk layout, the halo-inclusive overlap convention, and worked single-/multi-field examples.

source

Optional: this is a stub function until using WriteVTK loads HaloGridsWriteVTKExt. See the Parallel ParaView (pvtk) I/O guide for the on-disk layout, the halo-inclusive overlap convention (the opposite of the HDF5 extension's), and worked single-/multi-field examples.

Like global_reduce, but the reduced result is returned on every rank instead of only root. Use this for values every rank needs to keep going — a global CFL timestep bound, a global convergence check — rather than a value only meant for logging/output on one rank.

source
HaloGrids.global_reduce Function
julia
global_reduce(topology_or_grid, val, op; root::Integer=0)

Reduce val (typically a scalar diagnostic — a local max velocity, a partial sum, a convergence residual) across every rank sharing topology_or_grid's communicator, using reduction operator op (e.g. +, max, min, or any other operator MPI.Reduce accepts). The reduced result is returned on rank root; the return value on every other rank is whatever MPI.Reduce itself returns there (not meaningful — use global_allreduce if every rank needs the answer).

This is the scalar-diagnostic counterpart to gather!: where gather! assembles whole per-rank arrays into one global array, global_reduce combines one number per rank into one number. It does not know about halo widths or owned-vs-halo regions — reduce your own local data with plain Julia first (sum(A), maximum(A), excluding halo cells however is appropriate for that computation) to get one scalar per rank, then pass that scalar here. This split keeps the wrapper itself backend-agnostic: the local step can run on a CuArray/ROCArray however it likes, and only a host scalar ever needs to reach MPI, so no CUDA/ROCm-aware MPI transport is required (unlike a hypothetical direct reduction over device-resident array data).

HaloGrids.global_norm Function
julia
global_norm(topology_or_grid, A, p::Real=2)

Global p-norm of the data distributed across every rank sharing topology_or_grid's communicator: (sum(|Aᵢ|^p) over every element on every rank)^(1/p), matching LinearAlgebra.norm(A, p)'s convention (default p=2, the Euclidean norm) but summed over every rank's data, not just one. A is each rank's own local contribution — a plain array or a scalar; pass the interior only if A carries halo cells that would otherwise be double-counted, as with any other local reduction in this file.

Unlike global_sum/global_max/global_min, this is not a case of "reduce locally, then combine with the same operator": for p < Inf, only the sum of p-th powers is combinable across ranks (with a single p-th root taken at the very end) — combining each rank's own local norm directly (say, with global_sum) gives the wrong answer, silently, for any p other than 1. Because that mistake is easy to make by hand, this function does the full computation (local power-sum via plain sum, which runs on whatever backend A already lives on, then one cross-rank global_allreduce, then the root) rather than asking the caller to pre-reduce as the other functions here do. p=Inf computes the global maximum absolute value instead (the ℓ∞ norm) via global_max, since that one is directly combinable, and since the general sum(abs(x)^p, A) formula is not numerically meaningful at p=Inf. p=-Inf gives the global minimum absolute value. Other p <= 0 are rejected. Integer data is converted to floating point before powering, so it cannot overflow.

HaloGrids.nglobal Function
julia
nglobal(grid::Grid{N}, field::Field{T,N}, dim::Integer) :: Int

Size of the global domain in dimension dim, as seen by field — i.e. accounting for field's own halo width in that dimension. This is a per-field quantity, not a pure Grid property: two fields with different halowidths on the same Grid see different global sizes, because the number of cells duplicated across a rank boundary (2*halowidths[dim]) is part of the accounting.

Unlike the old package's nx_g/ny_g/nz_g, there is no separate "local array bigger/smaller than the base grid" adjustment: every Field exchanged on a Grid must have size(field.data) == grid.nlocal exactly (see check_fields), so that source of complexity in the old _adjust_nx_g simply does not exist here — this is the direct benefit of "one halo-width concept" for the coordinate layer, not just the exchange one.

Derivation: each rank owns nlocal[dim] - 2*halowidths[dim] cells that are not duplicated with a neighbor, plus, on a non-periodic domain, the outer halowidths[dim] cells at each of the two global edges are genuine domain cells (not halo from a neighbor that doesn't exist) and must be counted once, not zero times:

nglobal[dim] = dims[dim] * (nlocal[dim] - 2*halowidths[dim]) + 2*halowidths[dim] * !periods[dim]

HaloGrids.iglobal Function
julia
iglobal(grid::Grid{N}, field::Field{T,N}, dim::Integer, i::Integer;
        wrap_periodic::Bool=true) :: Int

Global index, in dimension dim, corresponding to local index i of field's array on the calling rank. Local index 1 is the first element of the local array including its halo — this matches the old package's ix_g/iy_g/iz_g convention.

On a periodic dimension, the global index wraps into 1:nglobal by default; pass wrap_periodic=false to get the raw (possibly <1 or >nglobal) index instead, e.g. to detect that a cell is a genuine wrap-around halo rather than a real neighboring cell.

Examples

julia
grid = HaloGrids.grid(topology((2,1)), (10, 8))
f = field(zeros(10, 8))
iglobal(grid, f, 1, 1)   # first local index (including halo) -> its global index

HaloGrids.coord_g Function
julia
coord_g(grid::Grid{N}, field::Field{T,N}, dim::Integer, i::Integer, dx::Real) :: Float64

Global physical coordinate, in dimension dim, of local index i of field's array on the calling rank, with grid spacing dx. Honors grid.origin[dim], grid.origin_on_vertex, and grid.centered[dim].

The domain's physical length is dx*(nglobal-1) when origin_on_vertex (the nglobal points are grid vertices spanning nglobal-1 cells) or dx*nglobal otherwise (the nglobal points are cell centers, each of width dx, so there is an extra half-cell margin at either edge). When centered[dim], this length is shifted so it is centered on grid.origin[dim]; otherwise grid.origin[dim] is the coordinate of global index 1 (vertex case) or the left edge of the domain (cell-center case).

Does not attempt to replicate the old package's staggered-array coordinate adjustment (nx_g(A)'s "array bigger/smaller than the base grid" case): since every Field on a Grid must share grid.nlocal exactly, that case cannot arise here — see nglobal.
