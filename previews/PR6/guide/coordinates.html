Coordinate helpers ​

Grid and Field carry sizing and halo-width information, but nothing about where a given local array index sits in the global domain — that is what the functions in src/coordinates.jl compute. They exist mainly for migration ease from ImplicitGlobalGrid.jl, whose nx_g/x_g/ix_g (and y_g/z_g/iy_g/iz_g) are used throughout JustRelax.jl and JustPIC.jl to build initial conditions, boundary masks, and diagnostics from physical position rather than local index.

Why these are per-field, not per-grid ​

In the old package, nx_g() was a grid-wide property: one active global grid, one global size. Here, the design deliberately has no grid-wide halo width — each Field declares its own — so the global size a field sees also depends on that field's own halo width: a wider halo means more cells are duplicated across each rank boundary, so a field with halowidths=(2,2) sees a smaller global domain than one with halowidths=(1,1) on the very same Grid. Every coordinate helper therefore takes both a Grid and a Field:

julia
nglobal(grid, field, dim)                    # global size in dimension `dim`
iglobal(grid, field, dim, i; wrap_periodic)  # global index of local index i
coord_g(grid, field, dim, i, dx)             # global physical coordinate of local index i

with nx_g/ny_g/nz_g, ix_g/iy_g/iz_g, and x_g/y_g/z_g as convenience wrappers for the first three dimensions, named and (for the coordinate functions) argument-ordered to match the old package's x_g(ix, dx, A) and similar.

One simplification falls out for free: every Field exchanged on a Grid must already have size(field.data) == grid.nlocal exactly (enforced by update_halo!/halo_exchange_start!). The old package's coordinate helpers spend real complexity on arrays that are staggered relative to the base grid (Vx = zeros(nx+1, ny, nz), for a face-centered velocity component) — that case cannot arise here, so there is no separate "array bigger/smaller than the grid" adjustment to reason about.

Worked example: initial conditions from physical position ​

nx_g, x_g, and friends let you build spatially-varying data (initial conditions, coefficient fields, boundary masks) so that a rank's result does not depend on how the domain happens to be decomposed — the same physical point gets the same value whether it is computed by one rank owning the whole axis or split across eight. The full example below (a 3D heat diffusion step, periodic in all three dimensions) builds two Gaussian anomalies each in heat capacity and temperature this way, then runs the explicit finite-difference update, exchanging T's halo every step.

Because the domain is fully periodic, total thermal energy (sum(Cp .* T) over the whole domain) is an exactly conserved quantity of this discrete scheme — every internal flux face is shared by two neighboring cells with opposite sign, so summed over a closed domain the update telescopes to zero, independent of how the domain is decomposed across ranks. The example checks this directly, which makes it a real correctness check rather than a doesn't-crash smoke test: a wrong halo exchange (this exact package once had one — see the note in halo exchange about the 2-rank periodic ring bug) breaks conservation immediately and visibly.

julia
# 3D heat diffusion on a periodic domain, decomposed across MPI ranks with
# HaloGrids.jl — a direct port of ImplicitGlobalGrid.jl's
# examples/diffusion3D_multicpu_novis.jl onto the new API, doubling as a
# worked example of the per-field coordinate helpers (nx_g/x_g/... in
# src/coordinates.jl): initial conditions are built from *physical*
# coordinates (two Gaussian anomalies each in heat capacity and temperature),
# not local array indices, so they must be identical however the domain is
# decomposed across ranks.
#
# The domain is fully periodic in all three dimensions, which makes total
# thermal energy (sum of Cp*T over the domain) an exactly conserved quantity
# of the discrete scheme: every internal flux face is shared by exactly two
# neighboring cells with opposite sign, so the update telescopes to zero when
# summed over a closed domain, regardless of how that domain is split across
# ranks — *provided* the halo exchange correctly delivers each neighbor's
# data. This example checks that conservation directly (`@assert rel_drift <
# ...` below), which makes it a real correctness check, not just a
# doesn't-crash smoke test.
using HaloGrids
import MPI

@views d_xa(A) = A[2:end, :, :] .- A[1:end-1, :, :]
@views d_xi(A) = A[2:end, 2:end-1, 2:end-1] .- A[1:end-1, 2:end-1, 2:end-1]
@views d_ya(A) = A[:, 2:end, :] .- A[:, 1:end-1, :]
@views d_yi(A) = A[2:end-1, 2:end, 2:end-1] .- A[2:end-1, 1:end-1, 2:end-1]
@views d_za(A) = A[:, :, 2:end] .- A[:, :, 1:end-1]
@views d_zi(A) = A[2:end-1, 2:end-1, 2:end] .- A[2:end-1, 2:end-1, 1:end-1]
@views inn(A) = A[2:end-1, 2:end-1, 2:end-1]

@views function diffusion3D()
    MPI.Init()
    t = topology((0, 0, 0); periods=(true, true, true))

    # Physics
    lam, cp_min = 1.0, 1.0                      # thermal conductivity, minimal heat capacity
    lx, ly, lz = 10.0, 10.0, 10.0                # physical domain size

    # Numerics
    nx, ny, nz = 32, 32, 32                      # local (per-rank) grid size
    nt = 50                                      # number of time steps
    hw = 1
    g = grid(t, (nx, ny, nz); origin_on_vertex=true)
    Tf = field(zeros(nx, ny, nz); halowidths=(hw, hw, hw))
    T = Tf.data
    Cp = zeros(nx, ny, nz)

    dx = lx / (nx_g(g, Tf) - 1)
    dy = ly / (ny_g(g, Tf) - 1)
    dz = lz / (nz_g(g, Tf) - 1)

    # Initial conditions, built from each cell's *global* physical coordinate
    # via the per-field coordinate helpers — identical result regardless of
    # how many ranks the domain is split across.
    for k in 1:nz, j in 1:ny, i in 1:nx
        xg, yg, zg = x_g(i, dx, g, Tf), y_g(j, dy, g, Tf), z_g(k, dz, g, Tf)
        Cp[i, j, k] = cp_min +
            5 * exp(-(xg - lx / 1.5)^2 - (yg - ly / 2)^2 - (zg - lz / 1.5)^2) +
            5 * exp(-(xg - lx / 3.0)^2 - (yg - ly / 2)^2 - (zg - lz / 1.5)^2)
        T[i, j, k] =
            100 * exp(-((xg - lx / 2) / 2)^2 - ((yg - ly / 2) / 2)^2 - ((zg - lz / 3.0) / 2)^2) +
            50 * exp(-((xg - lx / 2) / 2)^2 - ((yg - ly / 2) / 2)^2 - ((zg - lz / 1.5) / 2)^2)
    end
    update_halo!(g, Tf)  # halo of T must be valid before the first flux computation

    dt = min(dx * dx, dy * dy, dz * dz) * cp_min / lam / 8.1

    owned = (hw+1:nx-hw, hw+1:ny-hw, hw+1:nz-hw)
    total_energy() = MPI.Allreduce(sum(Cp[owned...] .* T[owned...]), MPI.SUM, g.topology.comm)
    E0 = total_energy()

    qx = zeros(nx - 1, ny - 2, nz - 2)
    qy = zeros(nx - 2, ny - 1, nz - 2)
    qz = zeros(nx - 2, ny - 2, nz - 1)
    dTedt = zeros(nx - 2, ny - 2, nz - 2)

    for _ in 1:nt
        qx .= .-lam .* d_xi(T) ./ dx                                            # Fourier's law: q_x = -λ δT/δx
        qy .= .-lam .* d_yi(T) ./ dy
        qz .= .-lam .* d_zi(T) ./ dz
        dTedt .= (1.0 ./ inn(Cp)) .* (.-d_xa(qx) ./ dx .- d_ya(qy) ./ dy .- d_za(qz) ./ dz)  # δT/δt = 1/cₚ (-∇·q)
        T[2:end-1, 2:end-1, 2:end-1] .= inn(T) .+ dt .* dTedt
        update_halo!(g, Tf)
    end

    E1 = total_energy()
    rel_drift = abs(E1 - E0) / abs(E0)
    @assert rel_drift < 1e-9 "total thermal energy drifted by a relative $rel_drift over $nt steps (expected exact conservation on a periodic domain)"

    MPI.Barrier(g.topology.comm)
    t.rank == 0 && println(
        "diffusion3D: energy conserved to a relative $rel_drift after $nt steps " *
        "on $(prod(t.dims)) rank(s) (dims=$(t.dims)).")
    MPI.Finalize()
end

diffusion3D()

Run it from the repository root:

sh
julia --project=. examples/diffusion3D.jl

or across several ranks:

julia
import MPI
MPI.mpiexec() do exe
    run(`$exe -n 8 $(Base.julia_cmd()) --project=. examples/diffusion3D.jl`)
end

The printed relative energy drift is at machine precision (typically 0.0 or on the order of 1e-16) regardless of rank count.
