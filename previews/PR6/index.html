HaloGrids.jlHalo exchange with explicit grids.

Build Cartesian MPI topologies, wrap local arrays, and exchange boundary data in Julia.

Get started
Explore the API

Explicit ownership

Topologies own communicators. Grids own communication caches. Fields declare their halo widths.

Two or three dimensions

Exchange multiple fields across Cartesian process layouts with periodic or nonperiodic boundaries.

Split-phase exchange

Start an exchange, perform independent work, then finish the final dimension's communication.

Per-field halos and overlaps

Each field declares its own halo width and overlap, so staggered and padded arrays share one grid.

Optional backends and I/O

CUDA arrays (tested on hardware), AMDGPU arrays (untested), CellArrays, parallel HDF5-style checkpoints, and ParaView output load as extensions.

Reductions and coordinates

Global sums, extrema, and norms, plus global index and coordinate helpers for each field.

How it fits together ​

A Topology arranges MPI ranks on a Cartesian lattice. Each rank owns a local array whose outer cells are halos, filled from its neighbors by update_halo!.

Continue with Topologies, grids, and fields for the model, Halo exchange for corners, face halos, and overlaps, or Hiding communication for the split-phase API.

Current scope ​

These pages describe the implementation in this checkout of version 0.1.0. The examples use CPU arrays. CuArray/ROCArray fields work as drop-in replacements wherever a Field wraps an array (see ext/HaloGridsCUDAExt.jl and ext/HaloGridsAMDGPUExt.jl); the CUDA extension is tested against real hardware, while the AMDGPU extension is a structurally identical port that has not been run against real ROCm hardware yet. save_hdf5/load_hdf5! (see ext/HaloGridsHDF5Ext.jl and the MPI/HDF5 file I/O guide) write and read Field data to/from a shared HDF5 file once HDF5 is loaded; no parallel-HDF5 build is assumed, so ranks take turns writing rather than writing simultaneously — see the guide for what that does and doesn't change for the caller. save_pvtk (see ext/HaloGridsWriteVTKExt.jl and the Parallel ParaView (pvtk) I/O guide) writes Field data to ParaView's parallel VTK XML image-data format once WriteVTK is loaded; unlike save_hdf5, every rank writes its own independent file (no shared-file write coordination needed), but halo cells are written rather than trimmed, and periodic topologies are not yet supported.
